# Visual paragraphs for new uploads

New uploads are stamped paragraph_pipeline=vision-paragraphs-v1 and pipeline_version=5.
Existing jobs without that marker keep their existing extraction path, including on retry.
No existing PDF, transcript, read-along map, or audio is regenerated by this change.

## Division of responsibility

- GPT-4.1 receives the target page image, adjacent page images, and immutable source-line IDs.
- PyMuPDF supplies original text glyphs and exact PDF coordinates, not paragraph boundaries.
- The model groups actual printed paragraphs and identifies headings, captions, equations,
  bibliography, diagram labels, and publication/author metadata.
- Each target source-line ID must be accounted for exactly once. Failed maps get bounded
  corrective retries rather than a silent fallback to merged page-sized narration.
- Cross-page and cross-column body continuations are stitched before summaries or speech.
  Floating figures and captions do not reset the body-paragraph continuation pointer.
- Captions are separate entries, ordered after a complete body paragraph rather than
  interrupting it. Source IDs keep their original page coordinates for the PDF reader.
- Bibliographic numeric brackets and author-year asides are removed from complete paragraphs.
  Meaningful bracketed measurements and recognized mathematical contexts are retained.
- Each complete printed paragraph has one source-audio entry and one paragraph timestamp.
  Existing TTS provider request splitting remains internal to that one audio entry.
- The existing summary and pronunciation model and configured source/guide voices are unchanged.

## Configuration

PDF2PODCAST_LAYOUT_MODEL defaults to gpt-4.1.
PDF2PODCAST_LAYOUT_CONCURRENCY defaults to 8, bounded between 1 and 16.
The backend reuses its existing OpenAI credentials and API request handling.
Visual page calls add image-token cost; adjacent-page context improves paragraph continuity.

Rendered pages live under each job's vision-pages directory.
Validated page maps use per-page fingerprinted, atomic caches under visual-paragraphs.
The assembled visual-structure.json and extraction-omissions.json retain an audit trail.
Content and playback manifests keep the version-4 client schema.

## Scope and limitations

This is hybrid visual layout extraction, not general OCR. Pages with no extractable text
are skipped, as before; fully image-only PDFs still require OCR.
Layout recognition is model-assisted, not guaranteed perfect for every publication layout.
The change does not reprocess old conversions or require a new iOS/macOS/web client.
